# P2-6 — validate() assumes each field’s rules value is an array. Given a string …

## Finding / 问题

- EN: validate() assumes each field’s rules value is an array. Given a string it emits a raw PHP warning ("foreach() argument must be of type array|object") and then passes the field silently, so a misspelled or mis-shaped rule entry validates nothing at all while reporting success — the same silent-discard shape this module removed from three other config paths in this round and last.
- 中文: validate() 假定每个字段的规则取值是数组。传入字符串时它抛出裸 PHP 警告（"foreach() argument must be of type array|object"），随后静默放行该字段——于是一条拼错或形状不对的规则什么都不校验却报告通过。这正是本模块在上一轮和本轮从另外三处配置路径上清掉的那种「静默丢弃」。
- Where / 位置: `src/Validator.php:148`
- Verification / 验证: reproduced / 已实证

- 2026-10-01 · `reviewer — migears-full-review` · `open` — filed from the 6th round.
- 2026-10-01 · `owner — migears-validator` · `fixed` — reproduced and fixed. Probe through this module's own `vendor/autoload.php` from a temp directory outside the repo confirmed the finding: `validate(['x' => 'abc'], ['x' => 'required'])` emitted `PHP Warning: foreach() argument must be of type array|object, string given in src/Validator.php:148` and returned `[]` — the field passed while validating nothing, exactly the silent-discard shape P2-1/P2-2/P2-5/P3-3 removed elsewhere. `validate()` now refuses a non-array rules value with the module's own `InvalidArgumentException` before the inner `foreach` (`src/Validator.php:146-159`); the same call now throws `Rules for field x must be an array, got string.` The `$rules` `@param` on `validate()` and `passes()` was widened from `array<string, array<int|string, mixed>>` to `array<string, mixed>` because the inner shape is now enforced at runtime rather than assumed by the type — without that widening PHPStan level 6 calls the guard dead code (`function.alreadyNarrowedType`), and this tree's `src/` idiom is to keep the type honest rather than suppress (cf. `migears-data-structure/issues/P3-5.md`). Pinned by `tests/ValidatorTest.php::testNonArrayFieldRulesAreRefused`; disabling the guard (`if (false && …)`) turns it red on `Failed asserting that exception of type "InvalidArgumentException" is thrown` with the same PHP warning. Documented in both README halves (`README.md:253` EN, `README.md:620` ZH, appended in place so no existing citation shifts). Level unchanged: still P2.
