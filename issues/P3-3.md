# P3-3 — A scalar or list config on a validator with no constructor parameters …

- 2026-10-01 · `maintainer — migears` · `fixed` — `fixed`. A config with nowhere to go is refused rather than dropped. `createFromScalar()` now returns `new $class()` only for a falsy scalar and otherwise raises `InvalidArgumentException` (`src/Validator.php:276-296`, refusal at `:290`), so `['email' => 'nonsense']` and the one-element list form both fail loudly instead of quietly degrading to a bare email check — the same loud failure an unknown key already got from `filterConfig()`. Falsy scalars are untouched on purpose: `['required' => 0]` and `['required' => '']` are this module's established way of writing "enabled, no config", pinned by `tests/ValidatorTest.php:395` `testLooseFalsyValuesDoNotDisableRule`, and the first version of this fix broke that case, which is how the narrower rule was found. `tests/ValidatorTest.php:217` pins the refusal; making the branch unconditional again turns it red. README documents the rule in both halves (`migears-validator/README.md`, under the list form). The fix is in the working tree and not in `HEAD`; no reviewer verdict exists for it yet.
