- 2026-10-01 · `maintainer — migears` · `fixed` — `fixed`. A scalar config is now pre-validated against the constructor signature before the call, so the raw `TypeError` no longer escapes a public entry point. `createFromScalar()` reflects the first constructor parameter, coerces through `coerceScalar()` as before, and refuses a value that cannot satisfy the declared type with the module's own `InvalidArgumentException` (`src/Validator.php:298-313`, refusal at `:307`; the `fitsParameter()` narrowing it consults is at `:326`). The message names the config value and the expected type: `['minLength' => 'abc']` now reports "MinLengthRule expects int for its first constructor argument, got string." `tests/ValidatorTest.php:230` pins it, and disabling the `fitsParameter()` guard turns that case red on "Failed asserting that exception of type \"InvalidArgumentException\" is thrown" — a `TypeError` arrives instead. Nothing else changed: a value the constructor accepts is still passed straight through, because the narrowing leaves any type it does not enumerate to PHP. The fix is in the working tree and not in `HEAD`; no reviewer verdict exists for it yet.
