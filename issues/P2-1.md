# P2-1 — The list-shaped config path passes the array straight to the …

## Finding / 问题

- EN: The list-shaped config path passes the array straight to the constructor: `["pattern" => ["/^[a-z]+$/"]]` throws `TypeError: PatternRule::__construct(): Argument #1 ($pattern) must be of type string, array given` and `["minLength" => [5]]` likewise. Enum survives only because its first parameter is `string|array`. The same syntactic shape is therefore valid for one validator and fatal for another, and the behaviour is pinned by a test as intentional but never documented.
- 中文: 列表形态配置会把数组直接传给构造器：["pattern" => ["/^[a-z]+$/"]] 抛 TypeError: PatternRule::__construct(): Argument #1 ($pattern) must be of type string, array given，["minLength" => [5]] 同样。enum 能活只因它的首参是 string|array。于是同一语法形状对一个验证器有效、对另一个致命，且该行为被测试固定为有意为之，却从未文档化。
- Where / 位置: `src/Validator.php:207-208`
- Verification / 验证: reproduced / 已实证

Probe against the module's own `vendor/autoload.php`: `['pattern' => ['/^[a-z]+$/']]` gives `passes('abc') === true` / `passes('ABC') === false`, and `['minLength' => [5]]` no longer throws. Pinned by `tests/ValidatorTest.php::testPatternListArrayConfigWorks` and `::testMinLengthListArrayConfigWorks`; reverting the guard (`createFromScalar(...)` → `new $class($config)`) turns both into the exact `TypeError: ... must be of type string, array given` this finding described. Now documented in `README.md:217-223` (both halves).
