## Verdict / 结论

The root cause of last round's P0 is only half fixed. The list form now works for enum but throws a raw TypeError for validators whose first parameter is scalar, and the map form still drops unknown keys silently — so a single typo turns a rule into a no-op.

上一轮 P0 的根因只修了一半。列表形态对 enum 可用了，但对首参为标量的验证器会抛原始 TypeError；映射形态仍静默丢弃未知键——一个拼写错误就能让规则彻底失效。

### P2

**P2-1** — `src/Validator.php:207-208`

- EN: The list-shaped config path passes the array straight to the constructor: `["pattern" => ["/^[a-z]+$/"]]` throws `TypeError: PatternValidator::__construct(): Argument #1 ($pattern) must be of type string, array given` and `["minLength" => [5]]` likewise. Enum survives only because its first parameter is `string|array`. The same syntactic shape is therefore valid for one validator and fatal for another, and the behaviour is pinned by a test as intentional but never documented.
- 中文: 列表形态配置会把数组直接传给构造器：["pattern" => ["/^[a-z]+$/"]] 抛 TypeError: PatternValidator::__construct(): Argument #1 ($pattern) must be of type string, array given，["minLength" => [5]] 同样。enum 能活只因它的首参是 string|array。于是同一语法形状对一个验证器有效、对另一个致命，且该行为被测试固定为有意为之，却从未文档化。
- Verification / 验证: reproduced / 已实证

**P2-2** — `src/Validator.php:292-305`

- EN: Map-form config silently discards unknown keys via `array_intersect_key`, so a typo weakens the rule instead of failing: `["minLength" => ["mn" => 5]]` passes "ab" (the key is dropped and minLength falls back to its default), and `["pattern" => ["patern" => "/^[a-z]+$/"]]` passes "123". The correct keys behave normally; the failure mode is "silently never fails".
- 中文: 映射形态配置用 array_intersect_key 静默丢弃未知键，因此拼错会让规则变弱而不是报错：["minLength" => ["mn" => 5]] 让 "ab" 通过（键被丢弃，minLength 回到默认值），["pattern" => ["patern" => "/^[a-z]+$/"]] 让 "123" 通过。写对键则正常；失败模式是「静默永不失败」。
- Verification / 验证: reproduced / 已实证

## Test gaps / 测试盲区

No negative case for a misspelled key in map-form config (the existing test only shows extra keys are ignored, not that a typo kills the rule); no documented boundary for the list form on non-enum validators; no assertion for `["enum" => true]` (empty allowed set) semantics.

无「映射形态拼错键」的负向用例（现有测试只证明多键被忽略，未证明拼错会使规则失效）；无「列表形态用于非 enum 验证器」的文档化边界；无 ["enum" => true]（空允许集）的语义断言。

## Verification protocol / 验证方式

- `./vendor/bin/phpunit` · `composer analyse` · `composer validate`
- Warning/notice/deprecation/risky flags in `phpunit.xml.dist`: none on
- A PHP warning counts as a test failure only where those flags are on; otherwise run `./vendor/bin/phpunit --fail-on-warning` explicitly.
- 只有在上述开关打开时 PHP 警告才会导致套件失败；否则请显式加 `--fail-on-warning`。
