## P0

### P0-1

- **Status / 状态**: Open
- **Where / 位置**: `src/Validator.php:189,272-285`
- **Verification / 验证**: reproduced and confirmed by reading the source
- **EN**: Array-shaped rule configuration is dropped wholesale. `filterConfig()` keeps only keys that match a constructor parameter name via `array_intersect_key`, and positional list keys are `0`, `1`, so they always filter down to nothing. Two consequences: `['enum' => ['A','B']]` becomes `allowed=[]` and **rejects every value** (both 'A' and 'C' were rejected), while `['pattern' => ['/^[a-z]+$/']]` falls back to the default `'//'` and **always passes** (both 'zzz' and 'ab' were accepted). The named form `['allowed' => [...]]` and the string form `'A|B'` behave correctly
- **中文**: 数组形态配置被整体丢弃。`filterConfig()` 用 `array_intersect_key` 只保留与构造参数名同名的键，而位置列表的键是 `0`、`1`，于是一律被过滤空。后果分两种：`['enum' => ['A','B']]` → `allowed=[]` → **拒绝一切值**（实测 'A' 与 'C' 都被拒）；`['pattern' => ['/^[a-z]+$/']]` → 落回默认 `'//'` → **恒通过**（实测 'zzz' 与 'ab' 都放行）。命名形态 `['allowed' => [...]]` 与字符串形态 `'A|B'` 正常

### P2-1
